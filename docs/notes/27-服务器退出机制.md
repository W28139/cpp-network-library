# 服务器优雅退出流程笔记

## 1. 核心目标
解决服务器只能通过 `Ctrl + C` 强制杀掉进程（可能导致数据丢失、连接未正常关闭、资源泄露）的问题。实现以下目标：
1. **捕获信号**：监听系统的终止信号（2 和 15）。
2. **逐层停止**：从业务层到底层网络引擎，按序停止工作线程池、从事件循环、主事件循环。
3. **资源释放**：确保所有线程汇合（join），对象正常析构，最后进程退出。

---

## 2. 流程图解
信号触发后的调用链如下：
`信号处理函数 (Stop)` -> `EchoServer::Stop()` -> `ThreadPool::stop()` & `TcpServer::stop()` -> `EventLoop::stop()`

---

## 3. 代码实现细节

### 第一阶段：信号注册与处理 (main.cpp)
信号处理函数必须能够访问到服务器对象，通常使用全局指针。

```cpp
// 全局对象指针，方便信号处理函数访问
EchoServer *echoserver;

void Stop(int sig) {
    printf("收到信号 %d，开始准备停止服务...\n", sig);
    echoserver->Stop(); // 触发业务层停止逻辑
    delete echoserver;  // 释放内存，触发析构函数
    printf("服务器已安全退出。\n");
    exit(0);            // 进程退出
}

int main(int argc, char *argv[]) {
    // 注册信号
    signal(SIGINT, Stop);  // 2: Ctrl + C
    signal(SIGTERM, Stop); // 15: kill 命令

    echoserver = new EchoServer(argv[1], atoi(argv[2]), 2, 3);
    echoserver->Start();
    return 0;
}
```

### 第二阶段：业务层与组件层停止 (EchoServer & TcpServer)
停止操作需要遵循“先停止新任务输入，后处理存量任务”的原则。

*   **EchoServer::Stop()**: 业务总控。
    *   先停止**工作线程池**（不在接收新业务）。
    *   再停止 **TcpServer**（不再接收网络 IO）。
*   **TcpServer::stop()**: 网络总控。
    *   停止**主事件循环**（不再接受新连接 Acceptor）。
    *   停止所有**从事件循环**（不再处理现有连接的收发）。
    *   停止 **IO 线程池**。

```cpp
void TcpServer::stop() {
    mainloop_->stop();         // 1. 停止主循环
    for(auto &loop : subloops_) {
        loop->stop();          // 2. 停止所有子循环
    }
    threadpool_.stop();        // 3. 停止网络线程池
}
```

### 第三阶段：核心引擎跳出循环 (EventLoop)
`EventLoop` 通常阻塞在 `epoll_wait`。仅仅修改 `stop_` 标志位是不够的，必须**唤醒**它。

1.  **修改标志位**：`stop_ = true`。
2.  **唤醒阻塞**：通过 `eventfd` 写入数据，让 `epoll_wait` 立即返回，从而能够检查到 `stop_` 标志。

```cpp
void EventLoop::stop() {
    stop_ = true;  // 设置退出标志
    wakeup();      // 向 eventfd 写入数据，破开 epoll_wait 的阻塞
}

void EventLoop::run() {
    while(stop_ == false) {
        std::vector<Channel*> channels = ep_->loop(); // 如果被 wakeup 唤醒，这里会返回
        // 处理事件...
    }
    // 循环结束，线程自然退出
}
```

### 第四阶段：线程池安全回收 (ThreadPool)
线程池必须等待所有正在执行的任务完成后再销毁。

```cpp
void ThreadPool::stop() {
    if(stop_) return;
    stop_ = true;
    condition_.notify_all(); // 唤醒所有阻塞在条件变量上的线程

    for(std::thread &th : threads_) {
        if(th.joinable()) th.join(); // 等待所有线程执行完当前任务并退出
    }
}
```

## 4. 关键技术点笔记

### 1. 为什么需要 `wakeup()`？
`EventLoop` 的 `run()` 方法大部分时间阻塞在 `epoll_wait()`。如果直接设置 `stop_ = true`，且此时没有网络事件触发，程序会卡死在 `epoll_wait` 处无法进入下一次 `while` 判断。
*   **解决方案**：使用 `eventfd`。`stop()` 调用 `wakeup()` 向文件描述符写 1 字节，强制 `epoll_wait` 返回，使程序立刻执行 `while(stop_ == false)` 的判断。

### 2. 线程汇合 (Thread Join)
在停止过程中，必须调用 `thread.join()`。
*   **目的**：确保主线程在子线程彻底清理完毕前不会销毁相关资源。
*   **后果**：如果不 join 导致主线程先执行了 `delete`，子线程可能正在访问已经失效的内存，导致 `Segmentation Fault`。

### 3. 信号处理的安全性
虽然在简单的笔记示例中直接在信号函数里 `delete` 是可行的，但在极其复杂的系统中，信号处理函数内应只做“设置标志位”或“写入 wakeupfd”的操作，真正的清理逻辑放在主循环外执行，这被称为**异步信号安全**。
