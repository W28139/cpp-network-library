# 线程池

C++11 最大的贡献之一就是引入了**标准的并发编程库**和许多**现代语法**。几乎所有现代的C++线程池都是基于C++11/14特性编写的。

## 1. 认识线程池

### 1.1 什么是线程池？他的作用是什么？

**通俗比喻**：
假设你开了一家餐厅（服务器）：

- **没有线程池的做法**：每进来一个顾客（任务），你就去大街上临时招募一个服务员（创建新线程）。顾客吃完走了，你就把服务员解雇（销毁线程）。如果顾客很多，你每天的时间都花在招人和解雇人上了（创建和销毁线程的系统开销非常大）。
- **有线程池的做法**：你一开始就固定雇佣 5 个服务员（创建 5 个线程，也就是**池**）。顾客来了，就让闲着的服务员去接待；如果 5 个服务员都在忙，新来的顾客就在大厅排队等候（任务队列）。服务员忙完手头的活，就自己去大厅叫下一个排队的顾客（线程复用）。

**结论**：线程池的核心就是 **“提前创建好一批线程”** + **“一个用来排队的任务队列”**。



### 1.2 需要掌握的 C++11 

#### 1. 基础现代语法（为了让代码更简洁）

- **auto 关键字**：自动类型推导，少写很多长长的类型名。
- **Lambda 表达式**：也就是匿名函数，用来极其方便地定义和传递“任务”。

#### 2. 函数的保存与传递（为了把任务放进队列）

- **std::function**：函数包装器。由于每个任务可能长得都不一样，我们需要一个统一的盒子把它们装起来，塞进任务队列里。
- **std::bind**（可选，现在常用 Lambda 替代）：用来绑定函数和参数。

#### 3. C++11 核心多线程库（线程池的骨架）

- **std::thread**：用来创建和管理线程。
- **std::mutex 与 std::unique_lock**：互斥锁。当多个服务员（线程）去大厅（队列）抢顾客（任务）时，防止他们打架。
- **std::condition_variable**：条件变量。当大厅没有顾客时，让服务员们睡觉休息（阻塞），一旦有新顾客来了，立刻叫醒他们（唤醒）。

#### 4. 异步与返回值（进阶，为了获取任务的结果）

- **std::future 和 std::packaged_task**：顾客点了一道佛跳墙（耗时任务），他可以先拿到一个取餐号（future），去干别的，等做好了再凭号码来取结果。



## 2. 补充基础知识

### 2.1 **Lambda表达式** 和 **std::function**

目标：**搞懂怎么把一段代码（任务）当作变量存起来，然后丢进队列里。**

#### 1. Lambda 表达式（匿名函数）

**Lambda 就是一个没有名字、可以直接写在函数内部的函数**

##### 核心语法格式：

\[捕获列表](参数列表) -> 返回值类型 { 函数体 }
*(注：返回值类型通常可以省略，编译器会自动推导)*

##### 关键点：什么是“捕获列表 [] ”？

这是 Lambda 最神奇的地方。普通函数不能直接使用它外面的局部变量，但 Lambda 可以通过 [] 把外面的变量“抓”进来用。

- []：什么也不抓，不使用外部变量。
- [=]：把外部变量按**值拷贝**的方式抓进来（只能看，不能改）。
- [&]：把外部变量按**引用**的方式抓进来（可以修改外部变量）。
- [x, &y]：x 按值抓取，y 按引用抓取。

```cpp
#include <iostream>

int main() {
    int count = 10;

    // 定义一个 Lambda 并把它存到变量 my_task 中
    // [=] 表示把外面的 count 拷贝进来用
    auto my_task = [=](int add_val) {
        std::cout << "Count 是: " << count << ", 加上参数后是: " << count + add_val << "\n";
    };

    // 像调用普通函数一样调用它
    my_task(5); // 输出：Count 是: 10, 加上参数后是: 15

    return 0;
}
```

#### 2. std::bind（任务打包器）

它在线程池里的核心作用：**把带有参数的函数，降维成“无参数”的函数。**

在线程池的队列里，所有的任务必须是统一的格式。最简单的格式就是**不带参数、没有返回值**的函数。如果你的原函数需要参数，就得用 **std::bind** 把参数提前“绑死”。

使用示例：

```cpp
#include <iostream>
#include <functional> // std::bind 在这里面

void print_sum(int a, int b) {
    std::cout << "Sum is: " << a + b << std::endl;
}

int main() {
    // print_sum 本来需要两个参数，现在我们用 bind 把 5 和 7 提前绑上去
    auto task = std::bind(print_sum, 5, 7);
    
    // 现在的 task 变成了一个不需要参数就可以调用的东西！
    task(); // 输出: Sum is: 12
    return 0;
}
```



#### 3. std::function（万能函数包装盒）

**为什么需要它？**
想一想，我们要造一个任务队列（大厅），队列里存放的是排队的任务（顾客）。
在 C++ 中，队列是这样定义的：std::queue<数据类型> task_queue;
问题来了：普通的函数、std::bind 绑出来的东西、Lambda 表达式，它们在 C++ 编译器看来，是**完全不同的类型**！
如果没有一个统一的盒子把它们装起来，它们就没法放进同一个队列里。

**std::function 就是这个统一的包装盒。**

**语法**：
`std::function<返回值类型(参数类型列表)>`

因为我们的线程池准备存放“没有参数，没有返回值”的任务，所以我们用：**std::function<void()>**。

示例代码

```cpp
#include <iostream>
#include <functional>
#include <queue>
#include <string>

void normal_function() {
    std::cout << "1. 这是一个普通函数" << std::endl;
}

void function_with_args(int a, std::string b) {
    std::cout << "3. 这是一个带参数的函数: " << a << ", " << b << std::endl;
}

int main() {
    // 准备一个任务队列，专门存放不需要参数、没有返回值的统一函数格式 void()
    std::queue<std::function<void()>> task_queue;

    // 情况1. 塞入普通无参函数
    task_queue.push(normal_function);

    // 情况2. 塞入 Lambda 表达式
    task_queue.push([]() {
        std::cout << "2. 这是一个 Lambda 表达式" << std::endl;
    });

    // 情况3. 塞入带参数的函数，通过 std::bind 封装
    task_queue.push(std::bind(function_with_args, 42, "Hello"));

    // 情况4(替代bind::). 也可以直接用 Lambda 捕获参数封装带参数函数
    int x = 99;
    std::string msg = "World";
    task_queue.push([=]() { function_with_args(x, msg); });

    // 执行队列中的任务
    while (!task_queue.empty()) {
        task_queue.front(); // 调用队首任务
        task_queue.pop();     // 移除已执行的任务
    }

    return 0;
}
```



### 2.2 **std::thread** 和 **互斥锁**

#### 1. std::thread（招募服务员）

创建一个 `std::thread` 对象，就相当于立刻启动了一个新线程去执行你指定的函数。

**基本语法**：

```cpp
#include <iostream>
#include <thread>

void worker_func(int id) {
    std::cout << "服务员 " << id << " 正在工作！" << std::endl;
}

int main() {
    // 创建一个线程，并立刻开始执行 worker_func(1)
    std::thread t1(worker_func, 1);
    
    // 主线程必须等待子线程执行完毕才能退出，否则会崩溃
    t1.join(); 
    return 0;
}
```

**在线程池中**：我们会创建一个 `std::vector<std::thread>` 来保存所有的“服务员”，让他们一直处于运行状态（写一个死循环，不断从队列里取任务）。

------



#### 2. std::mutex 与 std::unique_lock（给大厅上锁，防止打架）

`std::mutex` 叫互斥锁。你可以把它想象成大厅的一把**门锁**。服务员进去拿任务前，必须先锁门，拿完任务出来再开门。这样保证**同一时刻只有一个服务员在碰任务队列**。

而 `std::unique_lock` 是 C++11 提供的一个“全自动管家”，它利用 RAII 机制（对象创建时加锁，生命周期结束自动解锁），防止你忘了开门导致死锁。

**演示（多个线程抢数字）**：

```cpp
#include <iostream>
#include <thread>
#include <mutex>
#include <vector>

std::mutex mtx; // 全局锁
int shared_data = 0; // 共享数据

void add_data() {
    for (int i = 0; i < 10000; ++i) {
        // 创建 unique_lock，自动对 mtx 加锁
        std::unique_lock<std::mutex> lock(mtx);
        shared_data++;
        // 出了这个作用域，lock 对象销毁，自动对 mtx 解锁！
    }
}

int main() {
    std::thread t1(add_data);
    std::thread t2(add_data);

    t1.join();
    t2.join();
    // 因为加了锁，结果永远是 20000。如果不加锁，结果会小于 20000（发生数据竞争）
    std::cout << "结果: " << shared_data << std::endl;
    return 0;
}
```

------



#### 3. `std::condition_variable`（让服务员睡觉/唤醒，不浪费体力）

这是线程池的**灵魂**。
如果没有任务，服务员不能一直死循环问“有活吗？有活吗？”（这叫**忙等待**，会把 CPU 占用率飙到 100%）。
正确的做法是：如果没有任务，服务员就**去睡觉（阻塞等待）**；当有新任务放进队列时，主线程**摇铃叫醒他们（唤醒）**。

`std::condition_variable`（条件变量）就是这个铃铛。

- **wait(lock, 条件)**：睡觉。只要条件不满足，就一直睡，并自动把锁解开（让别人能进去放任务）。
- **notify_one()**：摇铃，叫醒一个正在睡觉的服务员起来干活。
- **notify_all()**：摇铃，叫醒所有服务员（通常在关闭线程池时用到）。



```cpp
#include <iostream>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <queue>
#include <functional>
#include <vector>
#include <atomic> // C++11 引入的原子变量，用于多线程安全地读写基本数据类型

// ================= 全局资源（餐厅大厅） =================
std::mutex queue_mutex;                  // 互斥锁：保护任务队列，防止多个服务员同时抢一个任务打架
std::condition_variable condition;       // 条件变量：大厅的“摇铃”，用来叫醒睡觉的服务员
std::queue<std::function<void()>> tasks; // 任务队列：存放顾客需求的队伍

// std::atomic 保证了这个 bool 变量在多线程下读写是绝对安全的，不需要额外加锁。
// 它就像餐厅门上的“营业/打烊”牌子。
std::atomic<bool> done(false);           


// ================= 服务员的日常逻辑 =================
void worker_thread() {
    // 服务员只要没被解雇，就会一直循环这个过程（死循环）
    while (true) {
        std::function<void()> task; // 准备一个空盒子，用来接接下来抢到的任务

        // 【核心细节 1】：为什么要用大括号 { ... } 把下面这段括起来？
        // 答案是控制锁的“生命周期”。我们只在“检查队列、取任务”时才需要锁。
        // 一旦取出任务，出了大括号，锁就自动解开了。
        // 这样服务员在“执行任务（干活）”时，是不占用锁的，其他服务员才可以继续去队列拿任务！
        // 如果不加括号，拿着锁干活，那就变成单线程了（因为别人都在等他解锁）。
        { 
            // 进门，自动上锁。如果锁被别人抢了，就阻塞在这里等别人解锁。
            std::unique_lock<std::mutex> lock(queue_mutex);
            
            // 【核心细节 2】：wait 的奇妙逻辑
            // condition.wait 会做三件事：
            // 1. 判断 Lambda 里的条件满足吗？（队列不空，或者餐厅打烊 done==true）
            // 2. 如果条件不满足（队列空且没打烊），服务员直接【原地睡觉】，并且【自动把手里的锁解开】！(这点极其重要，不然别人进不来放任务)
            // 3. 当被 submit_task 摇铃叫醒后，服务员醒来，【自动重新把门锁上】，然后再次检查条件。如果条件满足了，继续往下走。
            condition.wait(lock,[] {
                return !tasks.empty() || done.load(); 
            });

            // 醒来后往下走。如果是餐厅打烊了（done == true），而且队列里的任务都做完了。
            // 服务员就可以脱下制服回家了（return 结束线程）。
            // 注意：一定要等任务空了再走，保证餐厅关门前把已接的单子做完。
            if (tasks.empty() && done.load()) {
                return; 
            }

            // 如果没 return，说明队列里肯定有任务。我们把队列最前面的任务拿出来。
            // std::move 是一种 C++11 优化手段，相当于“掏空”原对象，避免不必要的拷贝。
            task = std::move(tasks.front()); 
            tasks.pop(); // 把任务从队伍里踢掉
            
        } // 大括号结束，lock 对象销毁，【门锁自动打开】。下一个服务员可以进去拿任务了。

        // 【核心细节 3】：在锁的外面执行任务！
        // 服务员拿到任务后，在门外干活。此时别的服务员也可以进大厅拿任务。
        task(); 
    }
}

// ================= 老板派发任务 =================
void submit_task(std::function<void()> task) {
    {
        // 同样，老板去队列放任务时，也得先锁门，防止放任务的时候有服务员正在拿任务。
        std::unique_lock<std::mutex> lock(queue_mutex);
        tasks.push(std::move(task)); // 把新任务塞进队伍
    } // 出了括号，解锁
    
    // 摇铃！通知大厅里正在睡觉的某一个服务员：“醒醒，来活了！”
    // notify_one() 只叫醒一个。如果想全叫醒，用 notify_all()。
    condition.notify_one(); 
}

// ================= 主程序 =================
int main() {
    const int num_threads = 4; // 决定雇佣 4 个服务员
    std::vector<std::thread> workers;

    // 1. 启动线程池（招募服务员）
    for (int i = 0; i < num_threads; ++i) {
        // emplace_back 是 C++11 往 vector 里放东西的更高效方法
        // 相当于执行了 std::thread(worker_thread)，立刻启动线程
        workers.emplace_back(worker_thread); 
    }

    // 2. 老板疯狂提交 10 个任务
    for (int i = 0; i < 10; ++i) {
        // 我们用 Lambda 包装一个打印任务传进去。
        // [i] 表示把当前的 i 按值捕获进去，这样每个任务都知道自己的编号。
        submit_task([i]() {
            std::cout << "执行任务 " << i << " 的线程 ID: " 
                      << std::this_thread::get_id() << std::endl;
        });
    }

    // （临时方案）主线程睡 1 秒，等服务员们把活干完。
    // 如果不睡，主线程直接往下走关闭线程池，可能有些任务还没来得及执行。
    std::this_thread::sleep_for(std::chrono::seconds(1));

    // 3. 优雅地关闭线程池
    done = true; // 挂上“打烊”牌子
    
    // 【核心细节 4】：为什么要叫醒所有人？
    // 因为可能有些服务员这时候还在睡觉（阻塞在 wait 那里）！
    // 如果不叫醒他们，他们永远不知道餐厅已经打烊（done=true），就会一直睡下去，导致程序卡死。
    condition.notify_all(); 

    // 4. 等待所有服务员收拾东西下班
    for (auto &t : workers) {
        t.join(); // join 会阻塞在这里，直到线程 t 执行完毕（触发了 worker_thread 里的 return）
    }

    std::cout << "所有任务执行完毕，线程池关闭。" << std::endl;
    return 0;
}
```



#### 解释std::atomic

##### 1️⃣ `std::atomic<T>` 是什么？

- **直白大白话**：它就是“原子变量”，专门用在多线程里，保证对变量的读写 **不会被中断，也不会出现脏数据**。
- **为什么需要它？**
  - 普通变量在多线程下同时读写，会发生竞态条件（race condition），可能导致线程看到的值不一致。
  - `atomic` 保证每一次读写都是 **完整不可分割的操作**，线程之间不会冲突。

------

##### 2️⃣ `std::atomic<bool> done(false);`

- `bool` 类型的原子变量，初始值是 `false`。
- **用途**：标记线程池是否已经关闭。
- 线程池工作线程每次循环都会检查这个变量：

```
if (tasks.empty() && done.load()) {
    return; // 队列空了且线程池关闭，就退出循环
}
```

- **为什么不用普通 `bool`？**
  - 如果用普通 `bool done = false;`，两个线程同时读写可能出现：
    - 一个线程刚写了 `true`，另一个线程没看到最新值
    - 或者 CPU 缓存导致“假死循环”，线程永远不退出
  - `atomic<bool>` 保证：线程立即看到最新值，读取/写入操作安全。

------

##### 3️⃣ `.load()` 和 `.store()`

- `done.load()` → 安全读取当前值
- `done.store(true)` → 安全写入新值
- 你也可以直接用 `done = true;`，C++11 以后 `atomic` 对 `operator=` 做了重载，也是安全的。

------

##### 总结比喻

- **普通 bool**：就像普通白板，大家同时在上面写字，可能互相擦掉。
- **atomic<bool>**：就像银行账户的流水，保证每次存取操作都被严格记录，不会被线程打断。





#### 解释`condition`

```cpp
condition.wait(lock,[] {
                return !tasks.empty() || done.load(); 
            });
```

##### 第一部分：后面的 Lambda 表达式 [] { return ... }

你还记得我们前面刚学的 Lambda 吧？在这里，它充当了一个**“检查条件”**。

```
{
	// !tasks.empty() : 任务队列不是空的（来客人了）
    // done.load()    : 线程池要关闭了（老板喊打烊了）
    return !tasks.empty() || done.load(); 
}
```

这个 Lambda 的意思是：**“要么来了新任务（表示我该干活），要么餐厅要打烊（表示我下班了），只要满足其中一个，就返回 true；如果都没满足，就返回 false（表示我可以继续摸鱼睡觉）。”**

##### 第二部分：前面的 `condition.wait(lock, ...)`

这是让线程执行“等待（睡觉）”的动作。当代码执行到这一行时，C++ 底层会按照以下极其严谨的步骤来执行：

**第一步：检查条件**
它首先会运行一下那个 Lambda 表达式。

- **如果返回 true**（比如队列里刚好有任务）：wait 直接结束，什么也不做！线程拿着锁，继续往下走，去取任务干活。
- **如果返回 false**（队列是空的，而且没打烊）：继续阻塞（睡觉）。

**第二步：睡觉并交出钥匙（极其关键！）**
如果条件是 false，线程就会在这一行**原地睡着（阻塞）**。
最神奇的是：**在睡着的一瞬间，它会自动把手里的 lock（互斥锁）解开！**

- **为什么要自动解锁？** 试想一下，如果服务员拿着大厅的门钥匙睡着了，老板（主线程）拿着新任务想进大厅放进队列，却发现门被锁死了，进不去，那整个系统就死锁了！所以睡觉前必须把锁交出来。

**第三步：被唤醒并重新抢钥匙**
当老板往队列里塞了任务，并调用了 `condition.notify_one()`（摇铃）时：
睡着的服务员会被惊醒。**醒来的第一件事，就是立刻去重新把 lock 锁上！**（如果别人正在用锁，他就在门外等一会，直到拿到锁）。

**第四步：醒来后的“回马枪”（再次检查）**
拿到锁之后，它**不会立刻往下走**，而是会**再执行一次 Lambda 表达式**进行检查！

- 如果还是 false（比如刚醒来，任务就被别的服务员抢光了）：叹口气，再次解开锁，继续睡。
- 如果是 true（确认真的有任务，或者真的打烊了）：wait 彻底结束，线程拿着锁继续往下执行代码。







### 2.3 **如何让线程池里的任务“返回一个结果”？**

继续用我们的餐厅比喻：

- **以前的任务**：老板对服务员说：“去把大厅扫了！”（这叫无返回值任务 void，服务员扫完就完了，老板不需要拿到什么实质性的东西）。
- **现在的任务**：顾客点了一道极其耗时的名菜“佛跳墙”（需要计算很久并**返回一个结果**）。顾客不可能在前台傻等几个小时，他需要**先拿一个“取餐号”（小票）**，然后去逛街，等逛完了，再凭小票来拿做好的佛跳墙。

在 C++11 中，“取餐号”叫 **std::future**，“带有取餐号的打包盒”叫 **std::packaged_task**。

------



#### 1. std::future（取餐小票）

**大白话**：它是一个神奇的盒子，里面现在是空的，但在“未来的某个时刻”，里面一定会被装入一个值。

- 你可以拿着这个小票去做别的事。
- 当你真的需要这个结果时，你调用 future.get()。
- 如果这时菜还没做好，你的主线程就会**卡住（阻塞）**在这里等；如果菜已经做好了，就会瞬间拿到结果！

#### 2. std::packaged_task（打包盒）

**大白话**：这是一个特殊的任务包装器。它把一个普通的函数包装起来，并且**自动为你生成一张对应的 std::future 小票**。
当这个包装好的任务被执行完后，它的返回值会自动“飞”进那张小票里。

------



#### 实战演示：不用线程池，先看看“小票”怎么用

为了让你看懂，我们先写一个非常简单的独立例子。**注意这里我用了你熟悉的 std::bind！**



```cpp
#include <iostream>
#include <thread>
#include <future>     // 必须包含这个头文件
#include <functional>

// 这是一个极其耗时的计算任务，它有返回值 int！
int calculate_sum(int a, int b) {
    std::cout << "后台厨师正在努力计算中..." << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(2)); // 假装算得很慢，要 2 秒
    return a + b;
}

int main() {
    // 1. 用 std::bind 把参数绑死，变成一个不需要传参的函数
    auto bound_func = std::bind(calculate_sum, 10, 20);

    // 2. 用 std::packaged_task 把这个函数打包！
    // 尖括号里的 <int()> 表示：这是一个不需要参数，且返回值为 int 的任务
    std::packaged_task<int()> task(bound_func);

    // 3. 【核心！】从打包盒里抽出一张“取餐小票”
    std::future<int> result_ticket = task.get_future();

    // 4. 找个服务员（新线程）去后台默默做这个任务
    // std::move 是必须的，因为打包盒是不允许复制的，只能“转移”给服务员
    std::thread t(std::move(task));

    // 5. 老板拿着小票可以先去干点别的事
    std::cout << "老板去喝杯茶..." << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(1)); 
    std::cout << "老板茶喝完了，来拿结果了！" << std::endl;

    // 6. 凭小票拿结果！
    // 如果后台还没算完，这里会卡住等；算完了就直接出结果。
    int final_result = result_ticket.get(); 
    
    std::cout << "拿到结果啦：10 + 20 = " << final_result << std::endl;

    t.join(); // 别忘了等服务员安全下班
    return 0;
}
```

#### 仔细体会上面代码的逻辑：

1. 原本的函数是直接 return a + b;。
2. 被 packaged_task 包装后，我们可以在它执行前，先抽出一张 future 小票。
3. 把 task 扔给另一个线程慢慢跑。
4. 我们在主线程用 result_ticket.get() 稳稳地拿到了另一个线程算出来的结果！

------



#### 这对我们的线程池意味着什么？

我们之前的线程池大厅（队列）是这样定义的：
`std::queue<std::function<void()>> tasks;`
它只能接收 void() 这种没有返回值的任务。

**这就产生了一个巨大的矛盾：**
我们的 packaged_task 是带有返回值的（比如返回 int，返回 string），类型五花八门。但我们的任务队列是个**“大杂烩队列”**，它强制要求所有任务必须长得一模一样，必须是 void() 类型！
