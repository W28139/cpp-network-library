# 回调

为什么使用它：核心区别与优势

| **维度**     | **普通函数调用 (Direct Call)**               | **回调函数 (Callback)**                                      |
| ------------ | -------------------------------------------- | ------------------------------------------------------------ |
| **调用关系** | **我主动叫你**：A 函数里写死了调用 B。       | **你回头叫我**：A 把 B 传给执行者，执行者在合适时机调用 B。  |
| **灵活性**   | **固定逻辑**：想换个功能必须改 A 的代码。    | **动态切换**：不改执行者代码，只需传入不同的回调即可改变行为。 |
| **执行时机** | **立即执行**：调用即运行，不运行完不往下走。 | **按需执行**：可以立即执行（同步），也可以等任务完成或事件发生再执行（异步）。 |
| **耦合度**   | **强耦合**：A 必须知道 B 的存在。            | **松耦合**：执行者只需知道回调的“样子”（签名），不关心是谁提供的。 |





### 1. 什么是回调函数？

**核心定义**：
回调函数是**“你传给别人的函数，让别人在合适的时机调用它”**。

**生活中的例子**：

*   **普通调用**：你去商店买东西，你在柜台等着，直到店员把东西给你。（同步，阻塞）
*   **回调模式**：你去网购，留下了**电话号码（回调函数）**。快递到了，快递员打你电话（调用回调），你去取件。（异步，非阻塞）

**在编程中**：
*   **调用者 (Caller)**：你的业务逻辑（Main 函数）。
*   **库/框架 (Library)**：底层的机制（比如 `Epoll` 循环、`Channel` 类）。
*   **问题**：库知道**什么时候**发生了事件（比如“数据来了”），但库不知道**怎么处理**数据（是解析 HTTP？还是写入数据库？）。
*   **解决**：你把处理逻辑打包成一个函数，传给库。库在事件发生时，回头调用这个函数。

---

### 2. C++ 中实现回调的三种进化形态

#### 形态一：上古神器 —— 函数指针 (C 语言风格)
这是最原始的方法，只能调用全局函数或静态成员函数。

```cpp
// 1. 定义回调函数的格式（签名）：返回值 void，参数 int
typedef void (*CallbackFunc)(int);

// 2. 你的业务逻辑
void my_handler(int fd) {
    cout << "处理连接 fd=" << fd << endl;
}

// 3. 底层库函数
void library_func(int fd, CallbackFunc cb) {
    cout << "底层检测到事件..." << endl;
    if (cb) cb(fd); // 触发回调
}

int main() {
    library_func(100, my_handler); // 传递函数指针
}
```
*   **缺点**：无法调用类的**非静态成员函数**（因为它接不住 `this` 指针），导致在面向对象编程中非常痛苦。

#### 形态二：现代 C++ —— `std::function` + `bind`/Lambda (主流推荐)
这就是你代码中正在使用的方式。它是一个**万能容器**，可以装下：普通函数、成员函数、Lambda、仿函数。

### 3. 为什么你的网络库代码需要 `std::bind`？

在你的 `Channel` 和 `Epoll` 代码中，核心矛盾在于：**底层库（Channel）想调用你的业务对象（Server）里的成员函数。**

#### 场景还原：
1.  **类 `Channel`**：负责管理文件描述符 `fd` 的事件。它有一个成员变量：
    
    ```cpp
    std::function<void()> readCallback_; // 这是一个空槽位
    ```
2.  **类 `Server`**：拥有具体的业务逻辑，比如 `newconnection`。
    
    ```cpp
    void newconnection(Socket* sock) { ... }
    ```

#### 困难点：
你不能直接把 `Server::newconnection` 赋值给 `readCallback_`。
*   因为 `newconnection` 本质上需要 **两个参数**：`(Server* this, Socket* sock)`。
*   而 `readCallback_` 定义为 `void()`，**没有参数**。

#### 解决方案：适配器模式 (`std::bind` 或 Lambda)

我们必须把那个多出来的 `this` 指针，以及那个 `Socket*` 参数，**提前绑定（绑死）**在回调函数里，把它伪装成一个无参函数。

**方式 A：使用 `std::bind` (你遇到的报错点)**
```cpp
// 意思是：把 newconnection 函数，绑定到 serverchannel 对象上，参数也固定为 &serversock
// 绑定后，产生的新对象不需要任何参数，正好符合 function<void()>
auto callback = std::bind(&Channel::newconnection, serverchannel, &serversock);

channel->setReadCallback(callback);
```

**方式 B：使用 Lambda (更现代，推荐)**
```cpp
// 意思是：定义一个匿名函数，捕获外部的 serverchannel 和 serversock
// 这个匿名函数本身不需要参数 ()，内部去调用真正的逻辑
channel->setReadCallback([=]() {
    serverchannel->newconnection(&serversock);
});
```

### 4. 深入剖析：回调函数的执行流程

结合你的 Reactor 模型（`Epoll` + `Channel`），回调流程是这样的：

1.  **注册阶段 (Main Loop)**:
    *   你创建了 `Channel`。
    *   你通过 `setReadCallback` 把 `Server::newconnection` 打包好，存入 `Channel` 的 `readCallback_` 变量中。
    *   此时函数**没有执行**，只是存起来了。

2.  **监听阶段 (Epoll Wait)**:
    *   `Epoll` 在内核中等待，程序阻塞。

3.  **触发阶段 (Event Happens)**:
    *   有新连接来了！`Epoll` 返回。
    *   `Epoll` 找到对应的 `Channel` 对象。
    *   `Epoll` 调用 `Channel::handleEvent()`。

4.  **回调执行 (Callback)**:
    *   `Channel::handleEvent()` 内部执行：`readCallback_();`
    *   这行代码会“穿越”回去，执行你最开始绑定的 `Server::newconnection`。

---

### 5. 总结：如何写好回调？

1.  **定义回调类型**：
    总是使用 `std::function`，不要用函数指针。
    
    ```cpp
    // 通用性最强
    using EventCallback = std::function<void()>; 
    using MessageCallback = std::function<void(const string& msg)>;
    ```
    
2.  **设置回调接口**：
    在底层类中提供 `set...` 函数。
    ```cpp
    void setReadCallback(EventCallback cb) { readCallback_ = cb; }
    ```

3.  **用户注册回调**：
    *   如果是**普通函数**：直接传名字。
    *   如果是**成员函数**（最常见）：
        *   首选 **Lambda**：`[&](){ obj->func(); }` （代码清晰，不仅能捕获 `this`，还能捕获局部变量）。
        *   次选 **Bind**：`bind(&Class::func, obj, args...)` （适合参数复杂的旧代码）。

你的代码报错正是因为在**注册回调**这一步，`bind` 的参数传递（`&serverchannel` vs `serverchannel`）搞错了对象层级。只要理解了**“成员函数需要对象实例指针来调用”**这个核心，回调就不难了。
