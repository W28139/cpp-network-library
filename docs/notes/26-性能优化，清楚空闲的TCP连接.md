# 性能优化，清楚空闲的TCP连接

### 为什么要清理？

* 空闲的connection对象是指长时间没有进行通讯的tcp连接
* 空闲的connection对象会占用资源，需要定时清理
* 还可以避免攻击



# 定时器&信号

定时器用于执行定时任务，例如清理空闲的TCP连接

* 传统做法：alarm()函数可以设置定时器，触发SIGALRM信号
* 新版linux内核把定时器和信号抽象为fd，让epoll统一监视

信号比较麻烦，本项目不使用信号

此时运行程序：

闹钟时间响了以后，会触发（1个主事件循环 + n个从时间循环 ） 次

主事件循环负责创建`Connection`对象，从时间循环负责`Connection`对象的事件，他们的功能是不一样，因此闹钟到了以后，做的事件不一样：

* 对于从事件：清理空余的Connection
* 对于主事件：无操作

因此需要区分主从事件循环，在`EvenetLoop`中，添加成员变量`bool mainloop_`来做区分

在构造函数，进行初始化，主事件用true，从事件用false



到目前为止，思路为：

设置一个闹钟事件，并把他挂到红黑树上，一旦有相应，对于的Channel就会发生事件(已经提前绑定好的)



下一步就是清理空闲的Connection对象

具体思路：

* 在事件循环中增加 map<int,spConnect>conn_容器，存放运行该事件循环上的全部Connection对象

* 如果超时了，从conns_ 中删除 Connection 对象
